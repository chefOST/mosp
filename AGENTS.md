# Project guidance

- At the start of every conversation, read README.md, then the relevant linked context, documentation and paper notes.
- Keep documentation concise; link canonical context instead of duplicating it.
- Distinguish published results, ChefOST experiments and proposals. Follow the shared evaluation definitions and document unresolved choices.
- Preserve `ryan/main` as the original imported history. Base implementation work on the populated contributor branch identified in README.md.
- Keep datasets, features, checkpoints, credentials and generated runs out of Git.
- Newer user instructions and supplied announcements take precedence over older notes.
